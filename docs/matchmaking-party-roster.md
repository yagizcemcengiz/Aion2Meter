## Independently authored parser and authority

The new compact 0092 grammar is an opaque 24-byte envelope after mask 00, a canonical count 1..5, exactly that many stable-profile rows, and one footer byte. Physical row order need not equal slot order. The old mask-08 one/two-member forms remain supported separately.

Stable-profile row facts are: mask 00/03/07; slot 1..5; optional runtime actor represented by a u32 that may be zero; origin server u16; scene server u16; length-36 canonical UUID; eight-byte token envelope; strict length-prefixed UTF-8 name; bounded complete suffix. The token envelope repeats the origin server in its final two bytes. That repeated origin is validated; the scene-server field is permitted to differ. This is a structural cross-server rule with no server whitelist. Mask-dependent optional text and bounded opaque suffix widths come from complete wire records, including variable-width canonical numeric prefixes. No gameplay interpretation is assigned to those opaque fields.

Parsing follows count and bounded candidate suffix widths; it does not scan for UUIDs/names/next rows, resynchronize, or accept an unconsumed frame. Ambiguous member sequences, unsupported masks/envelopes/cardinalities, duplicate slots, UUIDs, tokens or nonzero runtime claims fail closed. Multiple identical opaque-boundary interpretations do not create additional authority.

A fully validated 0D92 stable-profile join can establish named membership with no current runtime ID. A complete 0092 replacement also needs independently bound Self, either its current numeric actor and exact name, or a unique zero-actor origin/name pair matching independent stable Self profile evidence. Name alone cannot choose Self. This does not change the Self resolver.

Zero-ID rows use stable UUID/token identities, never actor zero. Their private dictionary locator is not exported or used for combat. Origin server, slot, membership provenance and stable class evidence remain attached to stable rows. Scene-server and runtime actor evidence are scoped to the current scene/epoch. Stable names survive handoff with zero totals and no rates.

For an ID-bearing current roster/join claim, an independent current 4536 must agree on both actor ID and exact name before damage becomes eligible. Members bind separately, so one far/unresolved member cannot stall the others. A zero-ID stable member cannot acquire a different runtime actor from display name alone: it waits for a current UUID/token-bearing claim and independent profile. Duplicate names and different servers remain distinct.

Valid inbound 1B92 retains the existing early-membership path; it is not damage evidence. Failed grammar no longer masquerades as authoritative empty membership and cannot newly lock that path forever. Valid full replacement, solo roster and disband still outrank stale status. C2S packets are never party authority. No arbitrary Other promotion, first-damage heuristic, backfill, scene-name condition or fixture character/ID whitelist.

The publication feed additionally emits diagnostic-only unresolved 0438 observations on the same complete-record timeline. A compact outer-frame watermark prevents repeat diagnostics without retaining packet bodies or adding publication dedup entries. This does not emit DamageEvent or change event authority. Existing transport, S2C fail-closed behavior, C2S non-authority, framing, combat decoding (including Unsupported 0x36), 3336/37 and 3336/3F Self binding/checkpoint rules are unchanged.
